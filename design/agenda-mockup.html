On touch targets: measured directly against site.css — .agenda-checkbox is 1.2rem (19.2px), .tag-chip/.pill padding produces roughly 24–28px, Bootstrap's own .btn-sm is ~28–31px. All of it is under the ~44px both platform guidelines and WCAG 2.5.8 ask for — the same finding Crane 1 slice 7 recorded for this exact page ("the Agenda, which nothing in Crane touched, is worse at 19–31px"). Below, every checkbox, pill, and button keeps its current visual size but gets a real ≥44px hit area around it.
On filtering: today it's split three ways — scope (Overdue/Today/This week) lives in the header as boxed stat cards, area lives as inline chips in the main column, tags live in a separate sidebar card. Three surfaces, two different shapes, for what's the same job: narrow what's showing. Below, area and tag collapse into one filter row under the composer — the same move TaskWorkspace's toolbar already made — and the header's scope counts become pills instead of cards, so the one page that reads "the whole day" speaks the same pill language the tasks in it already do.
On search and staleness: two gaps, not a styling problem. There's no text search anywhere on this page — scope, area, and tag chips all narrow by category, but there's no way to just type and find one task. And age_in_days lives on Daily's and the weekly review's own item types, not on the shared Task type this page's items are — so a task in "No due date" can sit for months with genuinely nothing on it: no due date, no age, no signal at all. Below, a search field sits beside the filter row, and a computed "Added N days ago" reuses agenda.ts's own ageLabel and its 7-day threshold exactly, the same wording Daily and the review already use, rather than a second phrasing for the same fact.
