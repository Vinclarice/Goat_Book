Why it renders like that today: TaskWorkspace.tsx is one of the last two components (with AgendaWorkspace) still styled through the old site.css — .form-control, .btn, .list-item — rather than the Tailwind system ProjectRoute and AreaRoute already use. Tailwind's own reset strips default browser chrome from every input, select, and button so utility classes can restyle them from scratch — and site.css's Bootstrap-era rules don't fully win that fight, which is why due dates, tags, and repeat controls render with no visible border or spacing at all. This isn't a polish pass, it's the same Tailwind migration the Projects pages already got, just for the one screen that carries the most fields per row.
On sorting: checked Item.Meta.ordering in models.py — it's ("position", "id"), a single stored integer set only by drag-and-drop (services.reorder_items). There's no due-date, alphabetical, or created-date sort anywhere in the API or UI today — manual order is the only order. Below folds in a real Sort control rather than just a passive "Overdue" section header, since that answers the actual gap directly: manual stays the default (today's behavior, untouched), and switching to "Due date" reorders the list and turns off dragging while it's active — the same on/off precedent canReorder already sets when a filter or search is active.

Drag handles and per-row actions step aside for a checkbox while selecting — same trade as Sort, one mode at a time rather than three interaction styles live on the same row. "Mark complete" and "Archive" bulk because they're already single, safe calls per task (changeStatus) run in a loop; editing due date, tags, or repeat stays per-task since "set every selected task's due date to the same day" isn't a real request anyone's made.

Considered simplifications, called out separately: (1) The due date pill is the input — no more separate "Overdue: Jul 31, 2026" line duplicating what the pill itself now shows in red. (2) Same for repeat: the pill select shows its own state, so the extra read-only "↻ Weekly" badge next to it goes away. (3) "Created Jul 29, 2026, 12:46 AM" becomes "Added 12 days ago" — Agenda's own age language (ageLabel), not a new rule — and a fresh task just says "Added today" rather than a timestamp nobody asked the minute of. (4) Each existing tag is now its own removable pill (click ×) instead of one text field pre-filled with "tag1, tag2" that you'd otherwise have to text-edit to remove one from — small, and it's the same updateTaskTags call either way. (5) Repeat and "+ tag" go quiet until a row is hovered or focused (same reveal the actions already used) — every task in the actual screenshot said "Doesn't repeat," so showing that control at rest on every row was mostly blank space with a label on it. Due date and any tags a task already has stay visible always; only the two rarely-touched controls hide. Any of these five can be left as-is if you'd rather keep the current behavior.
